# Legends roster — curated by hand.
#
# WHY THIS FILE EXISTS
# Keyword search cannot reach the top bands. SSR starts at 10M subscribers and UR
# at 50M, while the sourcing vocabulary (engine/discover.js, KEYWORD_SEEDS) is
# hobby/craft on purpose — it avoids news, politics and person-named channels,
# which matters when every result becomes a card carrying someone's likeness.
# That vocabulary essentially never surfaces a 10M+ channel, so a set built only
# from search tops out at SR and mints no chase card at all.
#
# Broadening the vocabulary would trade away the exact safety property it was
# chosen for. Who counts as a legend is human knowledge, not a query — so it goes
# in a file a person maintains and can argue with.
#
# FORMAT
#   One entry per line: @handle, a UC id, or a youtube.com channel URL.
#   Blank lines and everything after a # are ignored, so put the reasoning here.
#   Duplicates are dropped case-insensitively, first occurrence wins.
#
# COST
#   A handle costs 1 quota unit to resolve; UC ids batch 50 to a unit. A 200-name
#   roster is ~200 units against 10,000/day. Cheap — search is the expensive call
#   (100 units each), not this.
#
# USE
#   node tools/add-candidates.js catalog/legends.txt --dry-run   # cost + parse check
#   node tools/add-candidates.js catalog/legends.txt             # resolve and merge
#   node tools/build-set.js --slug legends --title "Legends"     # mint the deck
#
# TWO THINGS TO KNOW BEFORE ADDING NAMES
#   1. The India exclude applies here exactly as it does to search results. A
#      roster is a decision about who is interesting, never an exemption from the
#      local-risk hedge — and several of the largest channels on YouTube are
#      India-based, so they will be dropped. The tool reports how many.
#   2. Only ids reach catalog/candidates.json. Names written here are resolved to
#      UC ids and nothing else about the channel is ever committed.
#
# Roster begins below.
#
# ── First cut (2026-07-31): make SSR and UR reachable at all ──────────────────
# The first real build was N 27 · R 16 · SR 8 · SSR 0 · UR 0, so the top two
# bands did not exist and the UR reveal finish had never fired for a player.
# This roster exists to close that, not to be the final deck — WP9's deck sizes
# will grow it.
#
# Over-provisioned on purpose. Three things thin a roster between here and a
# card, and none of them are knowable before the run: a handle that has since
# changed resolves to nothing, the India exclude drops whoever declares IN, and
# a band that ends up holding one card is PRUNED by the build (a one-card band
# hands the player the same card every time it hits — see engine/setbuild.js).
# The minimum that survives is two per band, so ~12 names per band is the cheap
# insurance. A handle costs 1 quota unit; the whole roster is under 30 of 10,000.
#
# Expected bands are commented, not enforced. Subscriber counts move and the
# build assigns rarity from freshly hydrated stats, so a name drifting one band
# is normal and costs nothing.
#
# Skipped deliberately: channels built around child performers. The likeness
# question this project already carries is worse when the likeness is a kid's.

# ── SSR/UR depth for a 1,200-card printing (2026-08-01) ──────────────────────
# The printing target moved from 400 to ~1,200 cards, which wants UR 22 and
# SSR 79 per set. We had UR 17 and SSR 53, so the top two bands were the binding
# constraint on how large a set can be.
#
# WHY THIS IS ALL HAND-TYPED AND COSTS NO SEARCHES. A handle resolves for 1 unit
# from the 10,000/day bucket; a search costs 100 from a separate 100/day bucket
# that is nearly exhausted. Curation is the only way to grow these bands anyway —
# keyword search structurally cannot reach 10M+ channels.
#
# UR IS NEAR ITS CEILING AND THAT IS NOT A SOURCING FAILURE. English-language,
# creator-owned, non-India, not built around child performers, 50M+ subscribers
# is a set of roughly 15-30 channels worldwide. Past that the only 50M+ names
# left are record labels, kids channels and non-anglophone creators — the exact
# categories deliberately left unpinned. So UR grows by a handful here and the
# printing size is capped accordingly.
#
# Animation channels are called out because they are the one category that
# carries no likeness question at all — the "face" is a drawing the creator owns.
